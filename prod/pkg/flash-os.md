# 为设备安装系统

Ruyi 提供交互式设备安装向导，可以根据支持的设备和系统配置，获取镜像并调用相应工具写入目标存储。

Ruyi 目前支持如下两类安装方式：

- **dd**：通过主机直接向目标存储写入镜像，以 Milk\-V Duo 的 SD 卡安装为例。

- **fastboot**：通过 USB 与处于刷写模式的设备通信，以 LicheePi 4A 的 eMMC 安装为例。

> 烧录会覆盖目标存储上的数据。开始前请备份需要保留的数据，并确认设备型号、镜像和写入目标。

## 开始前准备

### 确认设备和硬件版本

先确认以下信息：

- 开发板的准确型号及硬件版本；

- 内存容量，以及可能影响镜像选择的存储配置；

- 本次准备写入 SD 卡、板载 eMMC，还是该设备支持的其他目标；

- 对应硬件版本的连接、供电和启动要求。

同一系列的不同型号可能使用不同镜像。不要因为名称相近，就选择其他型号或内存规格的配置。

本页实例分别采用 Milk\-V Duo 64M 和 LicheePi 4A 16G RAM。其他型号应根据实际硬件和向导中的可选配置操作。

### 确认 Ruyi 当前支持的设备与镜像

开始前，应已完成[安装 Ruyi](./install.md)中的安装验证、软件源检查，并按照[管理软件包](./manage.md)刷新索引。

运行安装向导可以查看当前索引提供的设备及系统配置：

```bash
ruyi device provision
```

首次确认只是进入向导；后续还会分别确认下载和烧录。

设备列表来自软件包索引，显示在列表中不代表主机已经识别到该设备。按名称选择设备后，还需要选择硬件变体和系统配置。

如果找不到准确的设备或系统配置，先检查索引是否已更新。仍然没有对应选项时，请停止使用相近型号尝试，转到问题排查与求助（链接待补充）。

部分配置会提供后续操作指引，请按向导实际显示的内容继续。

### 确认主机、连接方式、权限和所需工具

以下操作以 Linux 主机为基础。主机需要能够访问镜像下载地址，并留有足够空间保存下载文件和解包后的镜像。

| 安装方式 | 主机需要准备什么 |
| --- | --- |
| dd | 能识别目标介质的读卡器或连接设备；可调用的 dd、sudo；目标存储的写入权限。 |
| fastboot | 支持数据传输的 USB 线；与设备和镜像兼容、可从终端调用的 fastboot；可调用的 sudo；正确的 USB 访问权限。 |

可检查相应工具是否可调用：

```bash
# dd 路线
command -v dd sudo

# fastboot 路线
command -v fastboot sudo
fastboot --version
```

应能看到工具路径；fastboot 还应正常输出版本信息。缺少工具时，按主机发行版或设备官方说明安装。

Ruyi 会检查所需命令是否存在，但不会替用户安装这些主机工具，也不会自动完成 USB 权限配置。

使用普通用户运行 Ruyi。外部写入命令失败时，Ruyi 可能询问是否使用 sudo 重试。先查看失败原因；连接中断、镜像不匹配等问题不能通过提权解决。

Windows 用户即使已在 WSL2 中运行 Ruyi，也仍需单独解决设备访问问题。USB 接入通常需要额外配置；`wsl --mount` 对 USB、闪存盘和 SD 读卡器也有明确限制。参见[微软 USB 接入说明](https://learn.microsoft.com/en-us/windows/wsl/connect-usb)和[磁盘挂载说明](https://learn.microsoft.com/en-us/windows/wsl/wsl2-mount-disk)。

## 了解设备安装流程

### Ruyi 的交互式设备安装流程

本页统一使用：

```bash
ruyi device provision
```

`ruyi device flash` 是同一命令的别名，也会进入相同向导。

对于本页两种安装流程，主要交互顺序如下：

1. 阅读提示并确认进入向导。

2. 选择设备和对应硬件变体。

3. 选择希望安装的系统配置。

4. 如果存在可选版本，决定是否自定义各镜像包的版本。

5. 核对所需软件包，确认下载和解包。

6. 如果安装方式需要，输入目标存储路径。

7. 核对即将执行的操作，确认烧录。

8. 完成工具检查；使用 fastboot 时，还需自行确认设备已被识别。

9. 等待写入结束，再进行介质处理和设备启动检查。

无需提前手动下载本页实例中的镜像。向导会根据选择准备所需资源。

### 如何选择设备、变体、系统和版本

**设备**对应开发板型号；**变体**用于区分内存容量等硬件差异；**系统配置**决定本次需要的镜像组合。

一个系统配置可能包含多个软件包。例如，LicheePi 4A 的 RevyOS 安装需要系统镜像和配套 U\-Boot。

版本选择针对软件包。有多个可选版本时，向导才会询问是否自定义；选择默认版本时，Ruyi 会依据当前系统配置中的包约束选择版本。

自定义多个包的版本时，要核对它们是否属于匹配的发布组合。向导允许分别选择版本，不会替用户完成所有跨包兼容性判断。

菜单序号会随索引变化，请按名称和硬件规格选择。

### 如何判断使用哪种烧录方式

Ruyi 根据所选镜像配置及其安装流程确定使用的工具。

| 判断依据 | 对应方式 |
| --- | --- |
| 所选配置要求将存储介质接到主机，并输入目标整盘或分区路径 | 按 dd 路线准备。 |
| 所选配置要求设备通过 USB 进入刷写状态，并由 fastboot 识别 | 按 fastboot 路线准备。 |

同一开发板可能支持多种启动介质，以当前可选配置和烧录前显示的操作为准。

## 支持 dd 烧录镜像

### 适用场景与准备条件

这一路线适用于索引已配置 dd 安装流程、且目标存储能够作为块设备连接到主机的情况，例如通过读卡器写入 SD 卡。

开始前需要：

- 已确认与硬件匹配的系统配置；

- 已备份目标介质上的数据；

- 目标容量满足镜像要求；

- 主机能够识别目标介质；

- 目标介质上的分区已停止使用并卸载。

> 输入错误的目标路径可能覆盖主机系统盘。必须同时核对设备型号、容量、连接关系和挂载情况。

### 通用操作流程

1. **识别目标存储**。

2. 在接入目标介质前后，分别查看块设备信息：

```bash
lsblk -o NAME,PATH,SIZE,MODEL,SERIAL,TYPE,MOUNTPOINTS
```

1. 对比新增设备，并结合容量、型号、可用的序列号及下属分区确认身份。`MOUNTPOINTS` 用于查看挂载位置。参见 [lsblk 说明](https://man7.org/linux/man-pages/man8/lsblk.8.html)。

2. 如果目标或其下属分区正在承载主机的 `/`、`/boot`、`/home` 等目录，或被用于交换空间，请停止操作，重新确认设备。

3. **卸载目标介质上已挂载的分区**。

4. 关闭正在访问该介质的程序，通过主机的磁盘管理工具卸载目标介质上的分区，保留介质连接。

5. 再次检查挂载情况。不要为了通过检查而卸载主机正在使用的系统分区。

6. **进入 Ruyi 向导**。

```bash
ruyi device provision
```

1. 按实际菜单选择：

```text
<目标设备>
→ <对应硬件变体>
→ <系统配置>
→ <镜像版本，仅在需要时选择>
```

1. 以上是选择项占位符，无需输入尖括号文字。

2. **确认镜像下载与解包**。

3. 核对向导列出的镜像包。确认后等待资源准备完成。

4. **输入实际目标路径**。

5. 向导会说明需要整盘还是某个分区。输入刚才核对过的目标绝对路径：

```text
<目标块设备的实际绝对路径>
```

1. 整盘路径与分区路径不能混用。输入前若重新插拔过介质，必须再次检查路径。

2. **核对最终操作并开始写入**。

3. 检查向导显示的镜像文件与目标路径是否正确。只有确认目标就是准备覆盖的介质后，才同意烧录。

4. Ruyi 会调用 dd 执行写入。期间保持连接，不拔出介质，也不启动其他写入程序。若出现错误，先检查原因，不要连续确认重试。

### 实例：Milk\-V Duo

本例为 **Milk\-V Duo 64M RAM** 安装官方 Buildroot SDK 的 SD 卡镜像。

准备开发板、符合镜像容量要求的 microSD 卡、读卡器和供电线。需要查看启动日志时，可另行准备与板卡匹配的串口连接设备。硬件连接和启动要求参见 [Milk\-V 官方说明](https://milkv.io/docs/duo/getting-started/boot)。

按上面的通用流程识别并卸载 SD 卡分区，然后运行向导，按名称选择：

| 项目 | 本例选择 |
| --- | --- |
| 设备 | Milk-V Duo |
| 硬件变体 | 64M RAM |
| 系统配置 | Milk-V Duo Official buildroot SDK (64M RAM, SD card) |
| 镜像包 | board-image/buildroot-sdk-milkv-duo |

已核对的索引包含此镜像包的 `2.0.1` 版本。需要采用该版本时，在版本自定义步骤按版本名称选择；

下载和解包完成后，向导要求输入目标整盘路径。这里应填写 **SD 卡整盘的实际路径**；

最终确认时，再次核对镜像属于 Duo 64M，目标属于这张 SD 卡，然后开始写入。

本例的镜像选择不能直接用于 Duo 256M、Duo S 或其他存储安装方式。

### 完成后检查

先确认向导正常结束，且写入过程中没有错误。随后在主机执行：

```bash
sync
```

等待命令返回，再通过主机的磁盘管理工具安全弹出介质。Ruyi 的 dd 流程不会自动完成这两步。同步和卸载后再移除介质的要求，也见[设备镜像写入说明](https://docs.revyos.dev/docs/Installation/licheepi4a/)。

对于上述 Milk\-V Duo 实例：

1. 保持开发板断电，将 SD 卡插入板卡。

2. 按板卡要求连接电源并启动。

3. 观察启动状态；需要确认系统是否完整启动时，通过串口等官方支持的方式查看启动日志和登录提示。

写入命令结束只说明主机写入阶段完成。设备能够正常启动并进入预期系统后，才能确认本次安装可用。

## 支持 fastboot 烧录镜像

### 适用场景与准备条件

这一路线适用于索引已配置 fastboot 安装流程的设备。通常需要将开发板连接到主机，并使其进入能够接受刷写命令的状态。

开始前应确认：

- 使用支持数据传输的 USB 线，并连接正确接口；

- 已按对应硬件版本的说明进入刷写模式；

- 主机上的 fastboot 与所选设备、镜像兼容；

- 当前用户能够访问设备；

- 已备份设备中需要保留的数据。

进入刷写模式的按键、拨码和连接方式因设备而异。不要套用其他开发板的步骤。

为避免目标混淆，操作时只连接本次需要刷写的 fastboot 设备。

### 通用操作流程

1. **准备设备状态和连接**。

2. 按设备官方说明进入刷写模式，连接主机。提前完成 USB 权限配置。

3. **检查 fastboot 是否识别目标**。

```bash
fastboot devices
```

1. 应看到与目标对应的设备标识。输出为空、出现权限错误，或者无法确认设备身份时，先解决问题。

2. `lsusb` 显示了设备，不代表fastboot 已能正常访问。

3. **运行安装向导并选择配置**。

```bash
ruyi device provision
```

1. 按实际硬件选择设备、变体和系统配置；需要自定义版本时，核对系统镜像与引导加载器的对应关系。

2. **确认下载，核对即将执行的操作**。

3. 等待向导准备镜像，阅读最终操作列表。写入分区及可能出现的临时加载、重启步骤由具体设备流程确定。

4. 本页 fastboot 实例不需要输入主机磁盘路径。

5. **完成设备识别确认**。

6. 确认操作后，Ruyi 检查所需工具，并要求用户自行确认 fastboot 已识别设备。

7. 此时可在另一个终端再次运行：

```bash
fastboot devices
```

1. 确认目标可访问后，再返回向导继续。若识别失败，应退出并处理连接或权限问题。

2. **等待所有阶段完成**。

3. 后续写入由 Ruyi 调用 fastboot 执行。保持供电和 USB 连接，不在其他终端同时发送烧录命令。

4. 部分设备流程会在中途重启或重新连接，这是具体流程的一部分；

### 实例：LicheePi 4A

本例为 **LicheePi 4A 16G RAM** 向板载 eMMC 安装 RevyOS。

先确认核心板规格和底板硬件版本。准备主机、数据线及符合板卡要求的供电；需要观察启动过程时，可准备显示器或串口。

按对应硬件版本的说明检查 eMMC 启动设置。在板卡断电状态下，按住 BOOT 键并通过指定 USB\-C 接口连接主机，使其进入刷写模式。不同硬件版本的拨码要求有差异，接线前对照 [Sipeed 官方刷写说明](https://wiki.sipeed.com/hardware/en/lichee/th1520/lpi4a/4_burn_image.html)确认。

主机执行：

```bash
fastboot devices
```

确认输出对应本次连接的开发板。权限不足时，先处理主机 USB 访问权限，再进入向导。

运行向导，按名称选择：

| 项目 | 本例选择 |
| --- | --- |
| 设备 | Sipeed LicheePi 4A |
| 硬件变体 | 16G RAM |
| 系统配置 | RevyOS for Sipeed LicheePi 4A (16G RAM) |
| 系统镜像包 | board-image/revyos-sipeed-lpi4a |
| 配套引导加载器 | board-image/uboot-revyos-sipeed-lpi4a-16g |

这里的 `16G RAM` 指内存容量。还应确认实际存储规格满足所选镜像要求。

已核对的索引中，这两个软件包均包含 `0.20260504.0`，对应 RevyOS `20260504` 发布。选择这一发布时，应为两个包选择相匹配的版本，避免混用不同发布的系统镜像和 U\-Boot。

如果设备原先使用较旧的 RevyOS，开始前还应核对[官方升级注意事项](https://docs.revyos.dev/docs/Installation/licheepi4a/)中的 U\-Boot 环境变量处理要求；

确认下载和最终操作后，按向导要求再次检查 fastboot 设备。随后 Ruyi 依次执行：

1. 将配套 U\-Boot 加载到设备 RAM。

2. 重启进入该引导加载器，并短暂等待。

3. 写入 U\-Boot。

4. 写入 boot 镜像。

5. 写入 root 镜像。

这些操作由 Ruyi 调用 fastboot 完成，用户无需在另一终端重复执行。

### 完成后检查

确认所有阶段均正常结束。

对于上述 LicheePi 4A 实例，Ruyi 不会在最后自动重启进入系统。全部写入成功后，按板卡说明重新上电启动；从 eMMC 启动前应移除 SD 卡，并确认启动设置正确。参见 [RevyOS 启动说明](https://docs.revyos.dev/docs/Installation/licheepi4a/)。

通过显示器或串口观察启动过程，确认能够进入 RevyOS 并登录。

fastboot 设备在重启后消失，可能是正常切换，也可能是连接异常。最终应以设备进入预期系统为准。

如果中途某一步失败，保留错误信息，检查连接和失败阶段，再按问题排查与求助（链接待补充）处理。

## 遇到问题时

| 症状 | 先检查什么 |
| --- | --- |
| 找不到自己的设备 | 索引是否已更新；设备名称和型号是否准确。不要改选相近型号尝试。 |
| 没有可用镜像 | 硬件变体是否正确；当前配置是否只提供后续指引。 |
| 无法识别 SD 卡或块设备 | 介质、读卡器和连接是否正常；主机是否能显示对应块设备。 |
| 权限不足 | 当前用户的目标访问权限、sudo 配置，以及具体失败命令。 |
| fastboot 找不到设备 | 板卡是否处于正确模式；USB 接口、数据线和访问权限是否正确。 |
| USB 连接异常 | 数据线、供电、接口，以及设备是否正在按流程切换状态。 |
| 烧录中断 | 失败发生在哪个阶段；是否出现断电、断连或工具错误。 |
| 烧录结束但无法启动 | 镜像与硬件是否匹配；启动介质和设置是否正确；启动日志停在哪里。 |

以上问题的进一步处理统一进入问题排查与求助（链接待补充）。
