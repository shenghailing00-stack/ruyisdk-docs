# 管理软件包

本页介绍如何刷新软件包索引、查找并安装合适的资源、获取源码，以及更新和卸载软件包。

## 开始前确认

开始前，请确认已经安装 Ruyi，能够调用 `ruyi` 命令，并完成[安装 Ruyi](./install.md#first-use-configuration)中的“首次使用前配置”。

如果尚未确认软件源或网络访问情况，请先完成检查。执行过程中遇到索引访问异常，可进入问题排查与求助（链接待补充）。

以下操作示例在 Linux 或 WSL2 的 Linux 终端中执行。

## 获取与更新软件包索引

### 首次刷新索引

索引记录软件包名称、版本、适用条件和下载信息。首次查找或安装软件包前，执行：

```bash
ruyi update
```

Ruyi 会同步已启用的软件源。默认使用 RuyiSDK 的 `packages-index`；本地尚无该索引时，会自动获取。

远程索引同步成功后会显示更新完成提示，例如英文界面中的 `package repository is updated`。命令正常结束后，可以继续查询软件包。

如果更新失败，先检查错误信息及软件源访问情况，参见问题排查与求助（链接待补充）中的索引更新问题。

### 后续更新索引

准备查找新版本，或发现预期的软件包尚未出现在本地查询结果中时，再次执行：

```bash
ruyi update
```

这一步更新索引，不会自动升级已安装的软件包或 Ruyi 包管理器本身。

如果发现已安装软件包有更新，Ruyi 会提示可用的新版本。确认版本和适用条件后，按照本页“更新已有软件包”继续操作。

### 查看更新通知与新闻

刷新索引后，Ruyi 可能提示有未读新闻。查看新闻列表：

```bash
ruyi news list
```

列表包含编号、ID 和标题。根据当前列表中的编号阅读，例如阅读编号为 `1` 的新闻：

```bash
ruyi news read 1
```

也可以一次阅读全部未读新闻：

```bash
ruyi news read
```

读取的新闻会标记为已读。编号以当前列表为准，也可以使用列表中的新闻 ID 指定条目。

## 查找软件包

### 浏览或筛选可用软件包

尚不确定包名时，先浏览可用资源：

```bash
ruyi list --all
```

如果需要搭建开发环境，可以先只查看工具链分区：

```bash
ruyi list --category-is toolchain
```

找到相关名称后，再缩小范围。例如查找 GNU 上游工具链：

```bash
ruyi list --category-is toolchain --name-contains gnu-upstream
```

`--name-contains` 按包名中的文字进行匹配，区分大小写。多个筛选条件需要同时满足。

结果以“分区/包名”显示，例如 `toolchain/gnu-upstream`，其下列出各个版本。

### 查看软件包详细信息

确定候选软件包后，查看详细信息：

```bash
ruyi list --name-contains gnu-upstream --verbose
```

重点检查：

- 二进制文件支持哪些宿主平台和架构；

- 工具链面向哪个目标平台；

- 包含哪些组件及其版本；

- 是否有已知问题；

- 下载文件、大小和校验信息。

具体显示内容取决于软件包声明。上游版本未声明时，不应把 Ruyi 包版本直接当作上游版本。

## 判断软件包是否适合当前任务

### 区分软件包类型

查询结果中的分区可以帮助你判断资源用途：

| 分区 | 主要用途 |
| --- | --- |
| toolchain | 编译工具链 |
| emulator | 模拟器 |
| source | 源码资源 |
| board-image | 开发板系统镜像 |
| board-util | 开发板相关辅助工具 |
| analyzer | 分析工具 |
| extra | 其他资源 |

工具链等可安装资源通常通过 `ruyi install` 获取；源码包通过本页“获取源码”中的 `ruyi extract` 获取。

如果目标是为设备安装系统，请进入[为设备安装系统](./flash-os.md)，按设备及烧录方式完成准备。

### 理解版本与版本标记

安装时使用查询结果中的 **Ruyi 软件包版本号**。它采用 SemVer 格式，可能与软件自身的上游版本不同。

常见标记如下，实际显示文字可能随界面语言变化：

| 标记 | 含义 |
| --- | --- |
| latest | 该包最高的非预发布版本 |
| prerelease | Ruyi 将该版本识别为预发布版本 |
| latest-prerelease | 该包当前最高版本是预发布版本 |
| no binary for current host | 该版本未提供适用于当前宿主的二进制文件 |
| installed | 该版本被记录为已安装；二进制包按当前宿主判断 |
| downloaded | 相关下载文件已缓存，不代表软件包已安装 |
| has known issue | 该版本声明了已知问题，应查看详情 |

默认配置下，安装时选择最高的非预发布版本。启用预发布版本后，预发布版本也参与选择。

### 检查宿主平台 / 架构适用条件

安装前需要区分：

- **宿主机**：运行 Ruyi 和工具链等软件的机器。

- **目标平台**：编译产物最终运行的平台。

例如，在 x86\_64 Linux 主机上为 RISC\-V 设备构建程序，需要选择可在 x86\_64 Linux 上运行、面向相应 RISC\-V 目标的工具链。

软件包出现在列表中，不代表它支持当前宿主。先检查兼容性标记，再通过详细信息确认。

**Ruyi 先选择版本，再检查该版本的宿主支持情况**。 如果最高可选版本不支持当前宿主，安装会失败，不会自动改装较旧的兼容版本。此时需要查询并指定适用版本。

## 安装软件包

### 安装默认版本

确认 GNU 上游工具链适合当前任务后，执行：

```bash
ruyi install gnu-upstream
```

也可以使用完整名称 `toolchain/gnu-upstream`。

默认配置下，Ruyi 选择索引中最高的非预发布版本，获取对应宿主的文件并安装。所选版本已经安装时，会提示跳过。

安装完成后，查询本地安装状态：

```bash
ruyi list --name-contains gnu-upstream --is-installed y
```

检查实际安装版本旁是否有 `installed` 标记。

`--is-installed y` 筛选的是“至少有一个版本已安装”的软件包，结果仍可能显示该包的其他版本。只有具体版本旁的 `installed` 才表示该版本已安装。

### 安装指定版本

项目要求固定工具链版本时，可以明确指定：

```bash
ruyi install 'gnu-upstream(==0.20260201.0)'
```

下面的写法含义相同：

```bash
ruyi install 'gnu-upstream(0.20260201.0)'
```

需要选择不低于某版本的最高可选版本时，可以使用范围：

```bash
ruyi install 'gnu-upstream(>=0.20250401.0)'
```

多个条件使用逗号连接。例如，选择不低于 `0.20250401.0`、且低于 `0.20260201.0` 的最高可选版本：

```bash
ruyi install 'gnu-upstream(>=0.20250401.0,<0.20260201.0)'
```

支持的比较符为：

| 比较符 | 含义 |
| --- | --- |
| 无比较符或 == | 等于指定版本 |
| `!=` | 不等于指定版本 |
| `> / >=` | 大于 / 大于或等于指定版本 |
| `< / <=` | 小于 / 小于或等于指定版本 |

多个条件必须同时满足。请保留示例中包请求外侧的引号，并按示例紧凑书写表达式，避免括号、比较符被终端解释。

安装后，再通过 `ruyi list --name-contains gnu-upstream --is-installed y` 检查实际安装结果。使用版本范围时，尤其需要确认最终选中的版本。

### 按需安装预发布版本

默认不允许选择预发布版本；即使明确写出其版本号，也需要先开启相应配置。

先查询当前设置：

```bash
ruyi config get packages.prereleases
```

需要使用预发布资源时，开启：

```bash
ruyi config set packages.prereleases true
```

例如，获取索引中的 CoreMark 预发布源码：

```bash
ruyi extract 'source/coremark(==1.0.2-pre.20230125)'
```

这是源码包，因此使用 `extract`。默认解包到当前目录下的：

```text
coremark-1.0.2-pre.20230125/
```

`packages.prereleases` 是持久化的用户配置，会影响后续相关命令的版本选择；它不只作用于本次操作，`install` 也没有单独的预发布开关。

如果原设置是 `false`，并且只为本次获取临时开启，完成后恢复：

```bash
ruyi config set packages.prereleases false
```

恢复配置不会删除已经获取或安装的预发布资源。配置文件位置与完整配置说明见[配置与维护](./maintenance.md)。

### 重新安装已有软件包

需要恢复某个已安装版本的文件时，可以指定该版本重新安装：

```bash
ruyi install --reinstall 'gnu-upstream(==0.20260201.0)'
```

Ruyi 会先删除该版本原有的安装目录，再重新安装。该目录中的自行修改不会保留；重装失败时，原安装也不会自动恢复。

下载缓存有效时会直接复用，`--reinstall` 不表示每次都重新下载。

如果只写包名，Ruyi 仍会按当前索引和配置选择版本。因此，修复已有项目依赖时，应明确指定需要恢复的版本。

完成后检查该版本的 `installed` 标记。

## 获取源码

### 获取并解包源码

只需要获取源码时，可以直接使用 `extract`，无需先创建 Ruyi 虚拟环境。

例如获取 RuyiSDK 示例源码：

```bash
ruyi extract ruyisdk-demo
```

Ruyi 会获取源码归档并解包，完成后输出目标目录。

默认在当前目录下创建“包名\-版本”子目录。所选版本为 `0.20231114.0` 时，目录为：

```text
ruyisdk-demo-0.20231114.0/
```

获取源码不会将它登记为已安装的工具链等软件包。

### 指定版本或解包位置

需要固定源码版本并指定保存位置时，例如在当前目录的 `sources` 下解包：

```bash
ruyi extract -d ./sources 'ruyisdk-demo(==0.20231114.0)'
```

结果目录为：

```text
./sources/ruyisdk-demo-0.20231114.0/
```

`-d` 指定解包的父目录，默认仍保留“包名\-版本”这一层。

如果需要直接解包到指定目录，可以取消该层子目录：

```bash
ruyi extract --extract-without-subdir -d ./demo-work 'ruyisdk-demo(==0.20231114.0)'
```

此时源码内容直接放入 `./demo-work/`。

目标目录已经存在时，Ruyi 会继续使用它；同名文件可能被解包工具覆盖或触发提示。重新解包前，请保存已有修改，或选择新的目录。

只需要获取归档、不立即解包时：

```bash
ruyi extract -f 'ruyisdk-demo(==0.20231114.0)'
```

`-f` 表示只下载，不是强制覆盖。文件保存在 Ruyi 下载缓存中；Linux 默认位置为：

```text
~/.cache/ruyi/distfiles/
```

设置了 `XDG_CACHE_HOME` 时，对应位置为其下的 `ruyi/distfiles/`。`-d` 不改变下载缓存位置。

当前版本在只下载时仍可能创建空目标目录；空目录不表示源码已经解包。

### 确认后续工作目录

以使用 `-d ./sources` 的示例为例，进入：

```bash
cd ./sources/ruyisdk-demo-0.20231114.0
```

其他情况下，以命令输出的实际解包目录为准。不同源码归档内部还可能保留项目自己的目录层次，请结合解包结果和项目说明继续操作。

如果只执行了 `-f`，需要再次执行不带 `-f` 的 `extract` 才能得到工作目录；已下载且校验通过的缓存可以复用。

需要继续编译时，进入[配置开发环境](./dev-env.md)或对应开发案例。

## 更新已有软件包

### Ruyi 当前支持的更新方式

Ruyi更新软件包的流程是：刷新索引，检查新版本，再通过 `install` 安装需要的版本。

以 `gnu-upstream` 为例，先确认当前安装情况：

```bash
ruyi list --name-contains gnu-upstream --is-installed y
```

刷新索引：

```bash
ruyi update
```

查询可用版本，并检查宿主支持及已知问题：

```bash
ruyi list --name-contains gnu-upstream
ruyi list --name-contains gnu-upstream --verbose
```

确认准备使用的版本后安装。例如：

```bash
ruyi install 'gnu-upstream(==0.20260201.0)'
```

再次检查：

```bash
ruyi list --name-contains gnu-upstream --is-installed y
```

确认新版本旁出现 `installed` 标记。

新旧版本可以共存，安装新版前通常无需卸载旧版。先验证新版本满足项目要求，再决定是否删除旧版本。

Ruyi 包管理器本体的更新方法见[配置与维护](./maintenance.md)。

### 更新后对已有开发环境的影响

已有 Ruyi 虚拟环境继续引用创建时选定的软件包。安装新版本不会让这些环境自动切换。

要在开发中使用新工具链，请按照[配置开发环境](./dev-env.md)使用新版本重新创建相关环境，并完成项目验证。

确认旧环境不再需要原版本后，再卸载旧包。删除仍被环境引用的工具链或模拟器，会使相关命令无法正常使用。

## 卸载软件包

### 卸载已安装软件包

先查看已安装版本：

```bash
ruyi list --name-contains gnu-upstream --is-installed y
```

确认需要删除的版本不再被项目使用后，指定版本卸载。例如，仅在确实已安装且不再需要时删除：

```bash
ruyi uninstall 'gnu-upstream(==0.20250401.0)'
```

Ruyi 会列出待卸载的软件包及版本，并询问是否继续。检查后再确认。

也可以只写包名：

```bash
ruyi uninstall gnu-upstream
```

默认配置下，这会选择最高的已安装非预发布版本，**不会一次删除该包的全部版本**。启用预发布版本后，预发布版本也参与选择。

卸载完成后，再次查询安装状态。被删除版本应不再带有 `installed` 标记；如果还有其他已安装版本，该软件包仍会出现在结果中。

卸载前需要自行确认项目依赖，Ruyi 不会替你检查所有已有虚拟环境是否仍在使用该版本。

### 下载缓存和其他数据如何处理

卸载软件包不会同时删除其下载缓存，也不会删除软件包索引、Ruyi 本体或项目中已经解包的源码。

通常完成卸载即可，不必顺带清理全部数据。

需要回收下载占用时，相关选项是 `ruyi self clean --distfiles`；它清理全部下载缓存，无法按本次卸载的软件包单独选择。`--progcache` 清理的是 Ruyi 程序自身的缓存。

部分资源可能通过链接引用下载文件，因此清理前应先阅读[配置与维护](./maintenance.md)中的数据清理说明。完整的清理对象、影响范围和操作方法统一在该页维护。

## 遇到问题时

| 症状 | 首先检查 |
| --- | --- |
| 索引更新失败 | 检查网络和软件源访问；需要调整软件源时，返回[安装 Ruyi](./install.md#first-use-configuration)的“首次使用前配置”。 |
| 找不到预期软件包 | 确认索引已更新、筛选名称和分区正确。 |
| 指定版本无法匹配 | 检查 Ruyi 包版本号、表达式、引号，以及预发布配置。 |
| 提示当前宿主没有二进制包 | 查看该版本的宿主支持；需要时指定适用版本。 |
| 下载或解包失败 | 保留完整错误输出，检查下载连接、磁盘空间及提示缺少的解包工具。 |
| 卸载失败或安装状态异常 | 确认版本确实已安装，并检查近期是否切换软件源或修改过软件包目录。 |
| 本地索引或缓存异常 | 根据错误信息判断受影响对象，再进入对应排查流程。 |

以上问题的详细处理见问题排查与求助（链接待补充）。

安装状态查询依赖当前索引。切换软件源后，如果原有版本不再出现在索引中，不要仅凭查询不到就认定本地文件已经删除。

不要把清理全部缓存或全部软件包作为更新失败的默认处理。

## 下一步

- 只需要获取或管理软件包：完成本页操作即可结束。

- 准备搭建开发环境：携带已确认的工具链等软件包信息，进入[配置开发环境](./dev-env.md)。

- 已获取源码：按照项目说明继续准备和构建，或进入适用的开发案例。

- 准备为设备安装系统：进入[为设备安装系统](./flash-os.md)，按对应设备和烧录方式继续操作。
